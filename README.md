# AI 出海营销助手（离线 Demo）

这是一个面向出海营销顾问的工作台。Demo 以虚构的 **RelayChat AI** 为例：这家面向 Shopify 商家提供多语言 AI 客服的企业已有英文站和少量海外试用用户，需要验证英语市场的获客机会。

## 本地运行

在项目根目录运行（Python 3.10 或更新版本，无需安装第三方包）：

```sh
python server.py --port 4176
```

浏览器打开 [http://127.0.0.1:4176/](http://127.0.0.1:4176/)。使用预置数据和离线草稿即可走完演示，无需 API 密钥。

## 五步演示

| 题目环节 | 在 Demo 中怎么操作 | 可以看到什么 |
|---|---|---|
| 1. 潜在客户分析 | 在「候选企业」展开 RelayChat AI 的「评分证据」，点击「选择 RelayChat AI 跟进」。 | RelayChat AI 初始评分为 92/100。已有英文站和海外试用，且目标商家与价值表达不够清晰，因此适合优先跟进。 |
| 2. 潜在客户联系 | 在「客户触达」查看或编辑英文首封和跟进邮件，分别点击「人工确认拟发送」和「模拟发送」。 | 首封提出两周试点；跟进安排在 3 个工作日后，重点确认审核安排与可提供的资料。 |
| 3. 方案撰写 | 在「需求确认」载入原始模拟客户回复并点击「确认需求」，再到「两周方案」载入离线草稿并点击「确认方案」。 | 根据已确认需求形成两周获客试点：模拟预算 15,000 元，不做付费广告，重点验证符合画像的演示预约。 |
| 4. 执行交付 | 在「交付任务」点击「生成任务」，载入离线落地页草稿。把「英文落地页文案」任务推进至待审核，勾选「人工审核」，再推进至完成。 | 看到任务列表和一份可编辑的英文落地页文案，包含适用人群、价值表达、预约引导和 FAQ。另附一条 LinkedIn 文案样例。 |
| 5. 数据复盘 | 在「模拟复盘」点击「载入模拟营销数据」。 | 6 个演示预约达到 5 个的目标，但有效线索仅 10 条，占 33 条去重留资的 30.3%，低于 50% 的目标。下一轮将渠道文案和留资条件聚焦到拥有 2–10 人客服团队的 Shopify 商家，观察有效线索比例和有效线索到预约率。 |

## 设计、运营与实现

**产品思路：** 用同一个客户案例串起从筛选到复盘的过程，让顾问随时看清为什么跟进、方案依据是什么、下一步该做什么。

**运营方式：** 按服务匹配度、出海意愿、营销需求、联系可达性加权排序（30% / 30% / 25% / 15%），顾问可填写理由调整跟进顺序，系统分数保持不变。联系内容由人工确认；确认需求后才能推进方案，确认方案后才能生成交付任务。已确认方案改稿后要重新确认并复核任务，落地页改稿后也要重新审核。

**技术实现：** 浏览器原生 HTML、CSS 和 JavaScript，Python 标准库提供本地 HTTP 服务。候选评分与漏斗指标由 `logic.mjs` 计算，关键状态由 `workflow.mjs` 控制，模拟数据和离线模板存放于 `demo-data.mjs`。页面操作状态保存在浏览器本地。

上述是项目设计与开发时使用的 AI 工具。Demo 默认展示预置模板和模拟数据，演示时可离线运行。

## 演示范围

所有候选企业、联系人、回复、触达和复盘数据均为模拟。Demo 展示落地页与 LinkedIn 内容样例，未执行真实发布、联系客户、广告投放或上线部署。

可选的草稿生成接口兼容 OpenAI Chat Completions，通过服务端环境变量 `OPENAI_BASE_URL`、`OPENAI_MODEL`、`OPENAI_API_KEY` 配置。响应先作为候选草稿展示，经人工确认后才会替换正文。接口已通过本地模拟上游测试；真实供应商调用未验证。评审按上面的离线流程即可体验全部关键环节。

## 本地验证（可选）

```sh
node self-check.mjs
python -m unittest -v test_server
```

Node 自检验证需求与方案确认、改稿后重新审核、模拟发送校验和 AI 草稿接受。Python 测试使用本地模拟上游，覆盖未配置、成功、错误、超时和异常响应。
